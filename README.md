# RRSOS-PCC-Mods

*Red Rocket Solutions Operating System - Planet Crafter Companion - Mods*

Live-write mods for [The Planet Crafter](https://store.steampowered.com/app/1284190/The_Planet_Crafter/), as BepInEx 5 plugins. They place and change things in the **running** game. This repository is separate from the read-only dashboard ([RRSOS_PCC_Live](https://github.com/dkolln/RRSOS_PCC_Live)), which only observes the game and never writes to it.

The game has no official mod support or loader; the developers point players at BepInEx, at their own risk. These plugins are community mods in that sense.

## The mods

Each mod is its own project, builds to its own DLL, and installs into its own folder under `BepInEx\plugins`. None depends on another.

| Mod | Folder in `plugins` | What it does |
|---|---|---|
| **Base** (`src/Base`) | `RRSOS-PCC-Base` | At planetfall, or on request, builds the **T0 base** at the Prime template location: the **shell** of a base with some starter ore, and nothing that makes anything: 36 foundations, 10 pods, 54 crates with their labels, a craft station and the anchor lamp. No generators, heaters, vegetubes, drills, desks, chairs, screens or Terminal: the player crafts those. Crates are stocked from their labels. The base is a template (`src/Base/T0.json`, made from a save by `tools/capture-t0.py`) measured from the anchor foundation. Only in a new game (nothing crafted yet) and only on an empty site; judged from the world itself, so a game quit without saving starts over. It also tells its part of the start-up sequence in the chat and adds the base's location to the escape pod's welcome message. Chat: `/build` places it now, `/undo` takes back what it placed in this save. **After T0 the base does not grow by itself.** What keeps working is the upgrade chains (`upgrades.txt` in the mod's data folder), which swap any building in the world, base or not, for its next tier as soon as it is unlocked (Heater T1 > T2 > T3, drills, solar panels, spreaders, farms, hives, optimizers (the T1's fuse fills all three slots of the T2, and a T2 that is part full of one fuse is topped up), ore extractors, nuclear reactors, ...). The energy chain runs wind turbine, T1 and T2 solar, T1 and T2 nuclear, fusion; two of its links have a yes/no in the Base config: `SolarToNuclear` (off by default: T2 solar to T1 nuclear) and `NuclearToFusion` (on). A link that is off cuts the chain there, and the buildings past the cut keep upgrading among themselves. **Ore extractors** keep the ore of the vein they stand on; an extractor on no vein becomes a T3 of whichever ore in its `ore=` list (iron, silicon, titanium, cobalt, sulfur, magnesium) the world has the fewest of, so they spread evenly; they never bring back a piece you removed. **Extractor teleporters** (`Teleporters` in the Extractors section, off by default): once the Teleporter is unlocked, each ore extractor standing on a vein of a special ore (not iron, silicon, titanium, cobalt, magnesium or sulfur) gets a foundation beside it, a stair up to it and a teleporter on it named for its ore (laid out like the iridium extractor in the owner's save, following the extractor's direction; what already stands is kept, each extractor is done once). **Power:** the `[ OFF ]` button on the game's Energy window sets the energy output of every machine that makes energy (wind turbine, each solar tier) to 0, so everything that needs energy stops; generators built while it is off are switched off too; `[ ON ]` puts each output back. Nothing is removed from the world. It is kept per save (`power-state.txt`) and works only through those buttons, and a click is not reported on the terminal or in the chat (`Buttons`, `ButtonsX`, `ButtonsY` in the Power section of the config). A small guard also keeps the deconstruct tool working around pod doors and windows when the game's own hover code fails. When it stocks the template's labelled crates it reads item names from its own `aliases.txt` in the Base data folder (first made as a copy of the shared one, after that independent). |
| **Loadout** (`src/Loadout`) | `RRSOS-PCC-Loadout` | Chat: `/loadout` fits the top tier of every piece of personal gear through the game's own equip steps. A second call only adds what is missing and swaps a lower tier for its top tier. It also runs by itself at the start of a new game (only when nothing has been crafted yet and the gear is not already worn; `AutoAtPlanetfall` in its config) and adds a line to the escape pod's welcome message. |
| **Blueprints** (`src/Blueprints`) | `RRSOS-PCC-Blueprints` | At the start of a new game (nothing crafted yet, once per save) unlocks the blueprints the game otherwise hands out through blueprint chips, through the game's own unlock and without popups. The list is `blueprints.txt` in the mod's data folder (one group id per line; made from a save's `unlockedGroups`, so nothing that unlocks by terraformation is on it); delete a line to leave that blueprint locked. Off until `Enabled` is true in its config. With `UnlockStoryBlueprints` set to true (off by default) it also unlocks the blueprints the game hides in the story and the wrecks (treadmill, fridge, indoor bike, shower, lockers, vault, shelves, ...), from `story-blueprints.txt` in the data folder. |
| **Boosters** (`src/Boosters`) | `RRSOS-PCC-Boosters` | A **Boosters** screen in the build menu (1 Iron, 1 Aluminium, 1 Alloy; made from the Energy screen, icon `Boosters.png` in `CustomIcons`). Using it opens a window (the game's Energy window in booster mode; the real Energy screen is unchanged) where you pick a **beacon** (named for the job; a word like `heat`, `bees`, `tree`, `power`, `vege` picks the booster), the **booster** (heat, pressure, power, vege (a ring of eight T3 vegetubes, filled with the golden seed to begin with, the oxygen fuse), butterflies, bees, ecosystem, frogs, trees, grass, flowers, drone (four drone stations, on a 4 by 4 foundation pad behind the beacon, two at each end, facing each other; the drone type is chosen; beacon words `drone`, `station`)), the **machine tier**, the **optimizer** (none, T1, T2), its **fuses** (one optimizer each) and what to **fill** the machines with (No Fill, or one of the seeds, larvae or eggs for the kinds that take them; items that belong to another planet are not offered), then **Build**. Each such kind has a `[Fill]` setting in the config (a list the Mod Manager cycles) for what the screen starts with. Eight machines (four for drone): stacked at the beacon (heat, pressure) or in a 3 by 3 ring around the optimizers standing on it, with the dashboard's spacings. Free, through the game's own placement; what already stands in its place is kept; the beacon is removed when it is built. Tiers not unlocked are greyed out (`AllowLocked` offers them). Off until `Enabled` is true. |
| **Commands** (`src/Commands`) | `RRSOS-PCC-Commands` | A **Terminal** in the build menu (1 Iron, 1 Silicon, 1 Titanium, 1 Cobalt). Interact with it, type at the `C:\>` prompt (up to 100 characters, `InputLimit` in its config; the game's own text window allows far fewer), and the other mods' commands run and answer on the screen. The terminal knows nothing about other mods: any installed mod can register commands with it (see `TerminalApi`), and `/help` lists what has registered; `/cls` clears the screen. In a new game it also tells its line of the start-up sequence (see below). A placed terminal is saved in the world; without this mod the game drops it at the next load. |
| **Give item** (`src/GiveItem`) | `RRSOS-PCC-GiveItem` | Chat command `/giveitem <item> [quantity]` puts the item into your backpack, one at a time through the game's own add call. The quantity is 1 when left out; if the backpack has less room it takes what fits and says so. The item can be given by id (`Iron`) or by any whole name in this mod's own `aliases.txt` (in its data folder, first made as a copy of the shared one): `/giveitem add <item id> <name>` gives an item another name (for example `/giveitem add waterbottle1 water`). No terminal needed. |
| **Unlocks** (`src/Unlocks`) | `RRSOS-PCC-Unlocks` | In a **free-build** game the game switches its own "blueprint unlocked" popups off. This says `Unlocked: <name>` on the Commands terminal's screens when terraformation unlocks an item (the same unlocks the game's own alert watches). Nothing is said in a game that is not free build, where the game shows its own popup, and nothing for what was already unlocked when the world opened. It only reads the game and writes chat lines, so it is on by default. |
| **Mod Manager** (`src/ModManager`) | `RRSOS-PCC-ModManager` | A **Manage Mods** button on the main menu, above Quit. It opens a screen with every loaded mod on the left (RRSOS mods first, each shown on or off) and the selected mod's settings on the right, grouped by section: a switch for each yes/no setting, a button that cycles a fixed list, a text box for numbers and text, and a Reset for each. A change goes through BepInEx's own config entry, so it applies at once (for settings the mod reads while it runs) and is saved to the mod's `.cfg`; settings a mod reads only at start-up need a restart. A mod can also be switched off or on for the next start: its folder moves out of or back into `BepInEx\plugins` (to `plugins-disabled`); the Mod Manager itself stays on. Escape or Back closes the screen; if anything was changed it first asks whether to restart the game (it closes and starts again through Steam), or not now. |
| **Stacked crate** (`src/StackedCrate`) | `RRSOS-PCC-StackedCrate` | A build-menu item next to the storage crate: 3 Iron, places three Container1 on top of each other. The save only ever holds ordinary Container1 pieces. |
| **Resupply** (`src/Resupply`) | `RRSOS-PCC-Resupply` | Everything about storage crates and what is in them. **Fill on rename:** label a storage crate (Container1, 2 or 3) with an item's name and its **empty** slots are filled with that item, once, at the rename (`FillOnRename`; what is in the crate stays). The label must equal a whole name, ignoring case, spaces and punctuation: the item id, its name in the game, an extra name from the built-in table (for example `O2` for the oxygen capsule), or a name you add with the chat command `/resupply add <item id> <name>` (the chat command `/resupply` on its own fills every crate with its item) (for example `/resupply add waterbottle1 water`) or by editing `%LOCALAPPDATA%\RRSOS-PCC-Modsliases.txt` (`item id = name, name, ...`; yours win). A name that two items share is not guessed at. **Crate icon:** a recycle-arrows icon on the window of a storage crate (`Groups` in the config: Container1-3). One click fills that crate's **empty** slots with the item it is meant for: the item its label names (same names as Resupply), or else its demand (the drone-supply setting) when that is exactly one item. A crate with neither, or a demand of several items or a group like Seeds, gets no icon and nothing is guessed. The icon sits just above the game's sort icon, or one slot higher when the Trash mod's can is showing. `NudgeX` and `NudgeY` fine-tune the icon. It also adds a **Supply Manager** screen to the build menu (1 Iron, 1 Silicon, 1 Aluminium; the Energy screen underneath, with a warehouse on its face and in its build-menu picture): **Set Drone Demand** makes every crate that has an item (its label, or its category) ask the drones for that item and nothing else (a crate already set is left alone); **Set Drone Supply** makes every producer (ore and gas extractors, water collectors, beehives, an ecosystem, harvesting robots, ...) offer what it makes (a hive: honey and bee larvae; an ecosystem: its larvae and eggs; an extractor: the ore or gas it is set to; the rest: what they hold now); **Resupply** fills the crates; **Purge Extractors** (only from when the T2 ore extractor is unlocked until the T3 one is) leaves every ore extractor that stands on a vein holding only that vein's ore, deleting everything else in it (an extractor on no vein is left alone; `PurgeRequiresGroup` in the config); **Auto Top-Up** tops up the crates below `TopUpBelowPercent` full every `TopUpSeconds` (off by default, also a setting). Off until `Enabled` is true. |
| **Vehicle** (`src/Vehicle`) | `RRSOS-PCC-Vehicle` | Three buttons on the vehicle station's window (the one you open from the station's terminal, so they are only there at a station): **Spawn Rover** puts a new rover, with no gear, on the station's own spawn spot (not while any rover already exists in the game, and not while the spot is taken); **Gear Min** gives the rover at the station the first tier of every piece of rover gear it has no tier of yet (equipment size, inventory size, speed, oxygen, lights, beacon); **Gear Max** leaves it with exactly the top tier of each: other gear is taken out and deleted, gear already at the top tier stays. The gear goes into the rover's own equipment inventory through the game's add call. `ButtonsX` and `ButtonsY` in the config move the buttons. No terminal command and no Commands mod needed. Off until `Enabled` is true. |
| **Trash** (`src/Trash`) | `RRSOS-PCC-Trash` | A small trash can on the window of a storage container (`Groups` in the config: Container1-3, fridge, vault and locker by default). One click deletes everything in that container for good, with no question asked; the container stays. It sits one slot above the game's sort icon on the left of the container's grid, on the container side of the window. With `TrashOnPerson` (on by default) the same can also sits on the personal inventory window and deletes only the backpack, never the equipment. **Locks:** a middle click (or the right button: `LockClick`) on an item in any inventory window locks it, and again unlocks it (`LockItems`). A locked item shows the game's own lock icon, is skipped by the trash can, and stays behind when Move All moves the rest of the inventory. Locks are kept per save in `locks.txt` in the mod's data folder. `NudgeX` and `NudgeY` in the config fine-tune where it sits. |

**Messages go to the terminal.** What the mods tell the player while playing (upgrades done, a crate filled, an unlock, the auto top-up) is posted on the Commands terminal's screens (`TerminalRegistration.Notice`), not in the chat. With no terminal installed, or none built, the message is not shown (it is in each mod's log). The chat keeps the start-up sequence at planetfall and the answers to commands typed into it (`/build`, `/undo`, `/loadout`, `/giveitem`, `/resupply`).

**Adding a command to the terminal.** A mod with terminal commands looks the terminal up among the loaded plugins and registers each command by reflection, using only basic types (`src/Shared/TerminalRegistration.cs`), with the terminal declared as a soft dependency. No assembly is shared, and the mod works the same without a terminal.

Icons the mods draw themselves are kept in `%LOCALAPPDATA%\RRSOS-PCC-Mods\CustomIcons\<group id>.png`, apart from the game's own icons. A file already there is used instead of a freshly drawn one, so an icon can be replaced by dropping a PNG in; delete it to have it drawn again.

Every mod folder holds the DLL and a `mod.json` that describes the mod (id, version, commands, config file, data folder), so a tool can list and manage them.

Shared source lives in `src/Shared` (log, world state, placing a piece, the chat hook). Each mod compiles the files it needs into its own DLL, so a mod can be installed alone.

## Principles

- **Live writes, deliberately.** These mods change the running game. Each is off until `Enabled = true` in its own config file (`BepInEx\config\com.rrsos.pcc.<mod>.cfg`, created on the first start).
- **The game's own paths.** Pieces are brought to life the way the game loads a saved piece (a world object with its position, panels and colour, then `InstantiateWorldObject`), so the game saves them itself.
- **Logged and undoable.** Each mod writes `log.txt` in `%LOCALAPPDATA%\RRSOS-PCC-Mods\<Mod>\`. The Base mod keeps what it placed so `/undo` can remove exactly that.
- **Host only.** Nothing runs for a client in someone else's world.
- **Nothing of the game is redistributed.** The projects reference the game's assemblies in place, from your Steam folder, and take BepInEx from NuGet. Game files and the game's decompiled source are never copied into this repository.
- **Fragile by nature.** Some features use the game's private members (the chat command list, the group lists). A game update can break them; each failure is logged and the mod keeps going without that feature.

## Setup

1. Install the .NET 10 SDK and the game (Steam). Install BepInEx 5.4 (win x64) into the game folder and run the game once.
2. `powershell -ExecutionPolicy Bypass -File tools\setup.ps1` finds the game in any Steam library and writes `solution_private.targets`.
3. Close the game, then `dotnet build RRSOS.PCC.Mods.slnx -c Release`. Each DLL and its `mod.json` are copied to `BepInEx\plugins\<folder>\`. Start the game fully (a running game does not pick up a changed DLL).
4. Set `Enabled = true` in the config file of each mod you want.

To check a build without touching the game folder: `dotnet build RRSOS.PCC.Mods.slnx -c Release -p:PluginsFolder=<scratch folder>\`. To build one mod: `dotnet build src/Base -c Release`.

## Base mod request files

While a world is loaded, drop `build-now.txt` or `undo-now.txt` into `%LOCALAPPDATA%\RRSOS-PCC-Mods\Base\`; the mod acts within two seconds and deletes the file. The folder also holds `done.txt` (which saves were handled) and `undo.txt` (what was placed).

## New game start-up

In a new game the installed mods tell the chat, in turn: *New Planet Crafter Detected - Hacking Sentinel Corp.........*, *Preparing main base....* / *Done....*, *Accessing Loadout Parameters....* / *Done....*, *Processing Additional Commands......* / *Done.....*, *Accessing Blueprints......* / *Done...*, *Welcome Planet Crafter.* A mod that is not installed leaves its lines out. The mods share the order through a small table in memory and know nothing about each other. The welcome message in the escape pod is rewritten the same way: each installed mod adds its own paragraph, and it is signed Red Planet Solutions.
